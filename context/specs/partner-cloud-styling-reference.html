Styling & Structure Reference

Building Partner Cloud components that look native.

The Contentful1 ecHtf* component library is off-limits for edits — but it's the source of truth for visual language. This document extracts every pattern you need to reproduce that language in a new pc* component.

Constraint Do not modify any existing ecHtf* or contentful* component, Apex class, or custom metadata. New pc* components mirror the visual and structural patterns documented here — they do not import from or extend the existing components.
01 · Intent

Why this document exists

To let engineers building the Partner Cloud site achieve visual parity with the Contentful1 site without touching a single existing file.

The existing library encodes a specific visual language: a warm-neutral canvas with a strong brand-blue accent, dense Archivo display type against generous Hanken Grotesk body text, pill buttons, big rounded panels with soft shadows, 1200-pixel container, and a consistent section rhythm. If pc* components don't reproduce that language, the two sites will feel like different products stitched together.

Everything below is extracted verbatim from the compiled CSS of the existing components — the same values, same variable names, same clamp() functions. Copy them into new component files; do not import from the existing ones.

A note on data

This document covers visual patterns only. Because we cannot modify ContentfulService, contentfulService, or ecHtfContentService, the Partner Cloud site cannot reuse their single-space Contentful pipeline directly. The data layer for the new site needs its own resolution — track that separately from styling.

02 · Foundation

Design tokens

Every existing component declares the same set of CSS custom properties on :host. New components should do the same, with Partner-Cloud-specific values.

2.1 · The pattern

Each component owns its own :host { --brand: … } block. This gives every component a self-contained set of defaults it can render with. At runtime the existing HTF library overrides these via applyBrandTokens() which sets the same variables on the host element with values pulled from Contentful.

For Partner Cloud: hard-code Partner Cloud values in the :host block. No runtime override needed unless we plan multi-tenant Partner Cloud brands later.

03 · Type

Typography

Archivo for display (700–800), Hanken Grotesk for body (400–600). Loaded once by ecHtfSiteHeader; new components inherit them via the shared font tokens.

3.1 · Font loading

Fonts are loaded via a <link> injected into document.head by ecHtfSiteHeader._loadFonts(). As long as a Partner Cloud page includes the equivalent chrome (or loads its own <link> in the theme layout), Archivo and Hanken Grotesk resolve normally.

html — theme layout head (recommended) 
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link href="https://fonts.googleapis.com/css2?family=Archivo:wght@500;600;700;800&family=Hanken+Grotesk:wght@400;500;600;700&display=swap" rel="stylesheet">

08 · Chrome

Site header & footer

Partner Cloud can't use ecHtfSiteHeader/ecHtfSiteFooter directly (they contain HTF-specific logic). New pcSiteHeader/pcSiteFooter components should mirror these patterns.

8.1 · Header — key rules

  • Sticky at top — :host { position: sticky; top: 0; z-index: 100; }
  • Glassy backdrop — background: rgba(255,255,255,0.86); backdrop-filter: saturate(1.4) blur(14px);
  • Bar height — min-height: 78px
  • Bottom border — border-bottom: 1px solid var(--line)
  • Nav links — Archivo 600 · 15px · color: var(--ink-2) · hover → var(--brand-deep)
  • Underline on hover — animated ::after pseudo-element (matches HTF pattern)
  • Optional attribution bar above — background: var(--dark); min-height: 38px; for context or "made by Slalom" credit

8.2 · Footer — key rules

  • Dark background — background: var(--dark), text rgba(255,255,255,0.78)
  • Top padding — padding: 64px 0 30px
  • Column grid — grid-template-columns: 1.4fr 1fr 1fr 1fr; gap: 40px (brand block wider than link columns)
  • Column heads — Archivo · 13px · letter-spacing: 0.1em · uppercase · white
  • Link lists — flex-column, gap 11px, font-size 14.5px
  • Bottom strip — font-size: 12.5px; color: rgba(255,255,255,0.55); for copyright + legal links
  • Logo treatment — filter: brightness(0) invert(1) to render any brand logo as pure white
09 · Responsive

Responsive breakpoints

The existing library uses three breakpoints. Follow the same to guarantee grid behavior matches.

BreakpointWhat changes
max-width: 900px Hero grid collapses to single column · Feature split becomes stacked · Header nav collapses to hamburger (in existing header) · Media panels reflow to full width
max-width: 760px Stat band goes single column with top-border dividers · Process steps stack · Footer columns start collapsing
max-width: 640px Container padding shrinks from 28px → 20px · Hero CTAs stack vertically · Card padding tightens
Use fluid, not fixed

The existing library uses clamp(min, preferred-vw, max) aggressively for section padding, title sizes, and card padding. This means most sizing scales continuously — the breakpoints only exist for grid reshape moments, not for progressive size adjustments.

10 · Behavior

Data flow pattern (for reference)

Even though Partner Cloud can't reuse the existing Contentful service, the shape of the lifecycle every component follows is worth mirroring so behavior stays consistent.

javascript — the ecHtf lifecycle every section follows 
connectedCallback() {
  this._brandId = detectBrandId();
  this._load();
}

@wire(CurrentPageReference)
wiredPageRef(pageRef) {
  const brandParam = ((pageRef?.state?.brand) || "").toLowerCase();
  const resolved = BRAND_ORDER.includes(brandParam) ? brandParam : detectBrandId();
  if (resolved !== this._brandId) {
    this._brandId = resolved;
    this._load();
  }
}

async _load() {
  const brandId = this._brandId;
  const [theme, content] = await Promise.all([
    getBrandTheme(brandId),
    getSection("heroSection", brandId)
  ]);
  if (brandId !== this._brandId) return;  // race guard
  applyBrandTokens(this.template.host, theme);
  this._content = content || {};
  this._iconsReady = false;               // trigger icon re-injection
}

renderedCallback() {
  if (this._iconsReady) return;
  this._iconsReady = true;
  this._injectIcons();
}

What to mirror in Partner Cloud components

  • Race guard on async loads — if the "brand" (or in Partner Cloud's case, the config) changes mid-flight, discard the stale response.
  • Icon injection in renderedCallback — with an _iconsReady guard so it only runs once per data load.
  • Load in parallel — Promise.all for theme + content.
  • Set CSS custom properties on this.template.host — never on the child element. This is the LWC equivalent of the :host selector.
11 · Icons

Icon system

The existing library uses inline SVG icons injected via lwc:dom="manual". Partner Cloud components should copy the icon paths they need into their own module — do not import ecHtfBrandData.

11.1 · The pattern

html 
<span
  class="feature__item-icon"
  data-icon="check"
  data-size="22"
  lwc:dom="manual"
  aria-hidden="true"
></span>
javascript — renderedCallback 
_injectIcons() {
  this.template.querySelectorAll("[data-icon]").forEach((el) => {
    if (!el.innerHTML) {
      const size = parseInt(el.dataset.size, 10) || 24;
      el.innerHTML = getIconSvg(el.dataset.icon, size);
    }
  });
}

11.2 · Icon-shell helper (for a new pc module)

Copy this into a new pcIconLibrary.js module (utility-only, no template).

javascript 
const ICON_PATHS = {
  check:      '<path d="M5 12.5 10 17l9-10"/>',
  arrow:      '<path d="M5 12h14M13 6l6 6-6 6"/>',
  chevron:    '<path d="M6 9l6 6 6-6"/>',
  spark:      '<path d="M12 3v4M12 17v4M3 12h4M17 12h4M6 6l2.5 2.5M15.5 15.5 18 18M18 6l-2.5 2.5M8.5 15.5 6 18"/>',
  handshake:  '<path d="M3 12l3-3 4 3 2-2 2 2 4-3 3 3M7 9v6a2 2 0 0 0 2 2h6a2 2 0 0 0 2-2V9"/>',
  users:      '<circle cx="9" cy="8" r="3.2"/><path d="M3.5 19a5.5 5.5 0 0 1 11 0M16 5.2a3.2 3.2 0 0 1 0 6M17.5 19a5.5 5.5 0 0 0-3-4.9"/>'
  // …copy additional icons from ecHtfBrandData ICON_PATHS as needed
};

export function getIconSvg(name, size = 24) {
  const path = ICON_PATHS[name];
  if (!path) return "";
  return `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24"
    width="${size}" height="${size}" fill="none" stroke="currentColor"
    stroke-width="1.75" stroke-linecap="round" stroke-linejoin="round"
    aria-hidden="true">${path}</svg>`;
}
Why copy, not import

Importing getIconSvg from c/ecHtfBrandData would create a runtime dependency on the HTF library. A copied module keeps Partner Cloud fully independent — and it's cheap: the full icon set is under 3KB. Reference the source at force-app/main/default/lwc/ecHtfBrandData/ecHtfBrandData.js when picking icons to include.
